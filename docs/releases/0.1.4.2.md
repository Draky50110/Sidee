Sidee 0.1.4.2 generates connection credentials using the brand declared by the
TV. This addresses a compatibility gap reported on Toshiba VIDAA firmware:
the TV advertises `brand=tos`, while earlier versions always used `his`.

### Changes

- Read the brand identifier from the TV's UPnP descriptor and use it in the
  client identity, dynamic username and password derivation.
- Save the brand with the accepted pairing and reuse it when reconnecting or
  refreshing tokens. Existing sessions without a brand keep the `his` default.
- Retain static-first pairing, bounded profile fallback and PIN confirmation
  from 0.1.4.1. Static login credentials remain unchanged.
- The Windows ZIP builder also accepts an explicit output destination.
- Updated Windows, Apple Silicon and Intel Mac downloads include these changes.

### Toshiba trial

The reported Toshiba Z670 advertises `transport_protocol=3290` and `brand=tos`.
Firmware: `V0000.09.60N.Q0615` / `N.Q0615.9.61.00-a20260727u`. The official
VIDAA app can control this TV; Sidee 0.1.4.1 was refused before a PIN appeared.

Close the previous Sidee version and install the new download. On Windows,
extract the ZIP into a new folder and open `start-windows.bat`. On macOS, install
the matching Apple Silicon (`arm64`) or Intel (`x64`) DMG. The macOS app remains
unsigned and requires macOS 15 or later.

Find the TV and request a code. If pairing succeeds, try installing one app
and reconnecting after closing Sidee. If it fails, report the entire error and
the authentication result lines. Keep PINs and saved pairing credentials private.

Toshiba compatibility remains experimental. Automated checks verify brand
handling, existing sessions, PIN confirmation and packaged startup. The affected
TVs must still confirm that the new credentials permit pairing and tile installation.
