Sidee 0.1.4.1 updates the experimental Toshiba VIDAA connection flow after
reports that 0.1.4 was refused with `rc=5` on every authentication profile.

### Changes

- Fresh pairing tries static authentication first. A previously working
  profile still takes priority when pairing the same TV again.
- Static connections use a separate short MQTT identifier while preserving
  the identity already authorized in TV topics.
- Automatic background reconnect attempts are disabled. Each documented
  authentication profile is attempted once after an explicit refusal.
- A failed connection now includes the TV's advertised manufacturer, model,
  brand and transport protocol when available, without including MAC addresses,
  serial numbers, saved tokens or PINs.
- Windows and both macOS builds include these changes. Release automation
  accepts four-part hotfix versions; macOS keeps Apple's three-part version
  fields and records the complete Sidee version separately.

### Download and test

Download the package for your computer below. On Windows, close the previous
Sidee launcher, extract the ZIP into a new folder, restart the TV once, then
open `start-windows.bat`. On macOS, install the appropriate Apple Silicon
(`arm64`) or Intel (`x64`) DMG. The macOS app remains unsigned and requires
macOS 15 or later.

Find the TV and request a pairing code. If the PIN appears, enter it, try
installing one app, and verify reconnection after closing Sidee. If it fails,
report the entire new error, both TV models and firmware versions, and whether
the official VIDAA app still controls the TVs after the failure.

Toshiba compatibility remains experimental. The reported Z670 firmware is
`V0000.09.60N.Q0615` / `N.Q0615.9.61.00-a20260727u`. The connection changes pass
automated checks, but need confirmation on the affected TVs; this release
does not promise that every Toshiba model can pair or install tiles.
