Sidee 0.1.4 adds experimental Toshiba VIDAA connection support while retaining
the app installation and interface updates from 0.1.3.

### Changes

- When a TV rejects the initial connection with `rc=4` or `rc=5`, Sidee now tries
  the documented static and alternative VIDAA authentication profiles.
- Static firmware can request its PIN through a TV-state query. Pairing without
  tokens requires PIN acceptance and a successful app-list response.
- Sidee saves the working profile and preserves the accepted client identity
  when reconnecting or refreshing tokens. Static pairings do not attempt token
  refresh; a rejected pairing asks for a new PIN.
- Toshiba descriptors containing VIDAA identifiers can be discovered without
  requiring Hisense branding. Connection errors report the attempted profiles.

### Toshiba testing

The Toshiba Z670 with `V0000.09.60N.Q0615` / `N.Q0615.9.61.00-a20260727u` is a
reported target. Its official VIDAA app can pair and control it. Sidee pairing
and tile installation on this model still need confirmation on a real TV;
this release does not claim compatibility with every Toshiba model.

Download the Windows ZIP or the macOS package for your computer. Extract the
Windows download into a new folder and open `start-windows.bat`. On macOS,
install the appropriate Apple Silicon (`arm64`) or Intel (`x64`) DMG. Find your
TV, request its PIN, then try installing one app and reconnecting after closing
Sidee. The macOS app remains unsigned and requires macOS 15 or later.

For a failed trial, report the dashboard error and the authentication
profile/result lines. Keep PINs, pairing files, tokens, and dashboard access
links private.

Automated checks cover credential vectors, profile fallback, PIN confirmation,
saved sessions, token refresh, browser interactions, and packaged startup.
Hardware pairing and app installation require a real TV.
